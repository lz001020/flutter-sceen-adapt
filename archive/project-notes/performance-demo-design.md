## 展示版页面

```text
性能实验室
├─ 环境：设备 / 系统 / Flutter / commit / Profile / 刷新率
├─ 场景：指标计算 / 快速滚动 / 父级重建 / 配置切换
├─ 参数：固定预设、轮次、预热与测量时长
├─ 操作：开始 / 取消 / 复制结果
├─ 工作区：真实列表或移动标记
└─ 结果：逐轮明细、中位数、有效性说明、报告路径
```

展示模式可现场启动，基准模式由脚本传参驱动同一执行器。运行时禁用修改参数。取消和异常标记为无效，不参与汇总；未运行不能显示默认零分或预置 PASS。历史成绩标注日期和提交，不伪装成实时数据。

两种适配方案必须使用不同进程入口，不能在已创建的 binding 内点击切换引擎。首页介绍场景，宿主脚本分别构建/安装/启动对照。结束后生成宿主 HTML 报告，避免测量期间逐帧刷新图表干扰结果。

## 采样执行器（待实现）

```text
idle → ready → warmup → measuring → draining → completed
                 任一步异常/取消 → invalid（不计成绩）
```

- 共用 BenchmarkConfig、工作负载执行器、FrameCollector 和结果模型，各场景只实现工作量。
- ready 检查首帧、前台状态、有效视口、列表挂载与范围，不能把空滚动记为成功。
- 固定预热 2 秒，恢复初始位置再采样；重建测量 12 秒，快速滚动沿用 50×60ms、每次 80% 视口高度。
- 按帧时间戳筛选窗口，等待尾批 FrameTiming；endOfFrame 不保证 raster timing 已回调，不能用固定短延时冒充完整采集。
- 缺报告、工作量未完成、前后台切换或采样超时使本轮无效。取消移除监听并停止动画。
- 测量期间不逐帧打印、不请求网络图片、不更新统计图；结束后统一导出数据。
- 自动测试覆盖分位数、零帧、迟到批次、取消、重跑清空；Widget test 验证流程，真机 Profile 产生性能成绩。

## 公平性与口径

先比较截图、item 物理尺寸、缓存范围、字体策略与视口。帧数一致本身不证明工作量相同。切换设计稿会改变可见内容量，不直接当成同工作量对照。

固定设备、Flutter/依赖版本、刷新率和电源模式，记录温度/降频；构建完再测量。正式基线建议至少 6 轮 AB/BA 交替，使先后次数平衡；现有快速脚本为 3 轮，历史记录保留原口径。

逐轮展示指标及中位数、范围，不选最好的一轮。“每轮 p90 的中位数”与“合并所有帧的 p90”是不同统计量。

- buildDuration 是 UI 帧阶段耗时，不等于单个 Widget.build 函数耗时。
- rasterDuration 是栅格阶段耗时。
- totalSpan 是帧总跨度，不是简单的 build+raster，不代表 FPS 或触摸延迟。
- 60Hz 预算约 16.67ms，120Hz 约 8.33ms。build/raster 超预算比例分别报告；历史 janky16ms 是 totalSpan 超固定阈值计数，不是系统精确掉帧率。
- 没有内存或功耗实验，就不宣称减少内存、耗电。

突出技术难点可补充：

历史量化结果仅作为附条件的实验说明：

> 在 23127PN0CC 真机 Profile 的特定父级重建实验中，相对 ScreenUtil 内联尺寸写法，单轮 build p90 从 3.288ms 降至 0.903ms（约 72.5%），体现 const 子树复用收益。
