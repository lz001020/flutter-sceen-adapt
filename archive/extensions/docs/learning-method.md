# 技术点学习方法

本文档记录的是：遇到一个新技术点时，应该怎么学，怎么拆，怎么验证。

它不追求“学完所有 API”，而追求“尽快做出最小闭环，再按问题补深”。

## 1. 学习原则

### 1.1 先做闭环

先做一个能跑的最小版本，再扩展。

对 Widget 类技术来说，最小闭环通常是：

- 本地 mock 数据
- 显示一个最小卡片
- 点击能跳转
- 能刷新一次

不要一开始就做：

- 真实后端
- 登录态
- 多实例
- 复杂配置页
- 完整工程化

### 1.2 按问题学，不按目录学

不要按“文档章节”学，要按“卡住的问题”学。

常见问题只有几类：

- 数据从哪来
- 怎么展示
- 怎么刷新
- 怎么跳转
- 怎么处理异常
- 怎么做多实例

每次只回答一个问题。

### 1.3 先抓核心模型

不要把所有 API 当成重点。

先抓下面这些核心模型：

- 数据契约
- 生命周期
- 刷新机制
- 路由和跳转
- 异常降级
- 测试边界

API 只是这些模型的实现手段。

## 2. 学习顺序

### 2.1 第一步：定义目标

先明确这次要做什么，不做什么。

例如：

- 做一个 TODO List widget
- 数据来自本地 mock
- 不接真实后端
- 不做复杂编辑
- 先支持显示、点击、刷新

### 2.2 第二步：画数据流

把数据从 App 到 Widget 的链路画出来。

建议只保留一条主链路：

```text
App 数据
  -> 本地 mock / shared storage
  -> Widget 读模型
  -> 原生渲染
  -> 点击跳回 App
```

### 2.3 第三步：做最小实现

先做最少功能：

- 能显示
- 能点击
- 能刷新

这一步不要追求好看，只追求通路通了。

### 2.4 第四步：补边界

在闭环跑通后，再补：

- 空状态
- stale 状态
- error 状态
- 多尺寸
- 深色模式
- 动态字体

### 2.5 第五步：补工程化

最后再补：

- 单元测试
- snapshot / preview 测试
- 性能和功耗
- 发布检查
- 回滚方案

## 3. 每个技术点怎么学

### 3.1 Flutter 到原生桥接

只回答三个问题：

- 谁写数据
- 谁读数据
- 谁触发刷新

不要先研究太多 Channel 形式。

### 3.2 Android Widget

先区分两层：

- `AppWidgetProvider` / `RemoteViews` 的底层限制
- Glance 的上层写法

先用最小 Widget 跑通，再看 Glance。

### 3.3 iOS WidgetKit

先抓三件事：

- `TimelineProvider`
- `TimelineEntry`
- `WidgetFamily`

再补：

- App Group
- deep link
- Widget Extension 工程结构

### 3.4 数据契约

数据契约要先于 UI。

至少定义这些状态：

- ready
- empty
- stale
- error
- unauthorized

如果状态没定义清楚，后面 UI 和刷新都会乱。

## 4. 学习节奏

### 4.1 第一版

目标：

- 能显示
- 能点击
- 能刷新

### 4.2 第二版

目标：

- 加多尺寸
- 加状态
- 加异常降级

### 4.3 第三版

目标：

- 加多实例
- 加测试
- 加发布检查

不要一版里把所有问题都做完。

## 5. 什么时候算“学会了”

不是“看完文档”就算学会。

至少要能做到：

- 能独立设计数据契约
- 能独立搭一个最小 Widget 闭环
- 能解释刷新和降级
- 能处理多实例配置
- 能做基础测试
- 能说清楚哪些能力必须回到 App

如果只能复述 API，但不能做闭环，就还没学会。

## 6. 适合当前项目的学法

对于当前 TODO Widget 学习项目，推荐顺序是：

1. 先定 scope
2. 再定数据模型
3. 再做本地 mock 链路
4. 再做 Android Widget
5. 再做 iOS Widget
6. 最后补刷新、跳转、测试

这样学得快，也更接近真实开发。
