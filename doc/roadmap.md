# Roadmap

design_scale 专注 Android / iOS 单窗口应用的设计稿坐标适配，让业务组件直接使用设计尺寸。演进以保持 core 精简、提高实际接入可靠性为主。

具体任务按实际接入需求和验证结果确定。

## 优先方向

| 方向 | 要解决的问题 | 推进方式 |
| --- | --- | --- |
| 核心稳定性 | 已知交互异常、输入和设备指标边界 | 优先定位已知 iOS 交互问题；按风险补充高刷、多指、字体放大等验证，修复确认属于本库的问题 |
| Flutter SDK 兼容 | binding 与输入链路随 SDK 演进产生的差异 | 持续运行版本矩阵，升级支持范围时补充相关回归 |
| 常用插件兼容 | 原生视图、指针回调或自定义 binding 与全局适配的冲突 | 从实际接入需求选择插件，记录兼容版本、配置和限制；必要时提供针对性适配 |

## 候选能力

以下能力在出现明确使用场景后再立项：

- **局部原始坐标区域**：当第三方组件或原生视图确需独立于全局缩放时，评估局部反适配；布局、绘制、命中和嵌套行为须一致。
- **大屏适配策略**：先用示例说明原始窗口尺寸判断、设计稿切换与业务分栏；多个场景出现重复需求后，再考虑公共 API。

## 推进原则

每项工作对应一个具体问题和完成条件。已有验证可以复用；新增测试用于解决未决风险，性能结论限定于可复现的场景。

版本发布以[发布检查](release-checklist.md)为准，候选能力按独立需求推进。
